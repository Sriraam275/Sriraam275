### 📡 Automated CI/CD Deployment Monitor
![Impact](https://img.shields.io/badge/Impact-Failure%20Detection%3A%20Minutes%20→%20Under%201%20Min-1E3A8A?style=flat-square)

**Problem:** Deployment failures often went unnoticed until users reported issues — nobody knew a release had failed until it was already someone else's bad day.

**What I built:**
- A Python monitoring tool wired into a Jenkins pipeline that tracks deployment success/failure in real time
- Containerized with Docker + Docker Compose, deployed on an AWS EC2 (Ubuntu) instance
- Slack webhook alerting so the team hears about a broken deploy before a user does
- Hardened the repo against leaked secrets (`.gitignore` / `.dockerignore`) and documented it with architecture diagrams

`Python` `Jenkins` `Docker` `Docker Compose` `AWS EC2` `Slack API` `Git` `Linux`

**[🔗 View Repository](https://github.com/Sriraam275/cicd-deployment-monitor)**

### ⚙️ CI/CD Pipeline for Automated React App Deployment
![Impact](https://img.shields.io/badge/Impact-Docker%20Image%20Size%20Cut%2060%25%2B-1E3A8A?style=flat-square)

**Problem:** Every release meant someone manually building, pushing, and restarting services — slow, error-prone, and impossible to scale as a habit.

**What I built:**
- A Jenkins pipeline on AWS EC2, triggered automatically via GitHub webhooks on every push
- Dockerized the React app using multi-stage builds (Node.js + Nginx), cutting the final image size by an estimated 60%+
- Served the app through Nginx with the entire build-to-deploy flow automated by a custom shell script

`Jenkins` `Docker` `AWS EC2` `GitHub Webhooks` `Nginx` `Linux` `Shell Scripting`

**[🔗 View Repository](https://github.com/Sriraam275/react-jenkins-docker-pipeline)**

<br/>

### 🔒 Secure & Scalable AWS VPC Network Architecture
![Impact](https://img.shields.io/badge/Impact-Zero%20Direct%20Internet%20Exposure-1E3A8A?style=flat-square)

**Problem:** A flat network puts backend and database resources one misconfiguration away from being exposed directly to the internet — not a risk worth taking.

**What I built:**
- A custom VPC with public and private subnets, using an Internet Gateway and NAT Gateway to control outbound traffic in one direction only
- A layered security model with Security Groups and NACLs at both instance and subnet level
- Validated the design with a public-facing web server and a fully isolated private backend — confirmed zero direct internet exposure for backend resources

`AWS VPC` `EC2` `IGW` `NAT Gateway` `Security Groups` `NACLs`

**[🔗 View Repository](https://github.com/Sriraam275/secure-aws-vpc-architecture)**
